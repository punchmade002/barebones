01

The run, in order

This is execution order, not the historical stage numbers: diagram cropping (7) runs before scheme matching (5b) because a crop only needs segmented parts, while an official answer needs the part list to match against. Pick a step to read what it consumes, what it writes, and what stops it.

02

The keyless worker loop

There is no ANTHROPIC_API_KEY anywhere in the pipeline. Each model stage writes its jobs to disk and stops; a subagent fills them in; you re-run the same command to collect. Step through it.

03

Where everything lives

Every stage is resumable because its output is a file, not memory. _data/ is generated and gitignored; the repo-root JS is what the app actually loads. Click any step name to jump back up to it.

04

Beside the run

Nine modules never appear in run.py’s stage list, and the pipeline does not work without them. One is a hand-authored contract the publish gate blocks on. One is a worker stage you invoke yourself. The rest are the machinery the stages sit on, plus the repair commands for stores that already shipped.

05

Where it refuses to continue

A file existing is not proof its contents are good. These are the checks between the model and the student, with the constants they read from config.py.

Then the publish gate’s sixteen checks

gate.blockers() is the list of BLOCK findings; merge.run refuses on any one of them. WARN and INFO are printed and survive.

06

Driving it

The /run-pipeline skill runs the whole loop for you. By hand it is the same command re-invoked until it prints PIPELINE COMPLETE.

# the loop, by hand python3 run.py biology --estimate-cost # inspect the next stage, request nothing python3 run.py biology # advance one model stage, or finish # prints WORKER NEEDED <dir> → run pipeline-worker on it → re-run the same line
